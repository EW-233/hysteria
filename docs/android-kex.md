# 灰狼 KEX 安卓测试包 0.11.0

本包基于 SFA 1.14.2 的安卓界面，接入现有 `hysteria2-kex` 原生出站。应用名称为「灰狼 KEX」，包名 `dev.greywolf.kex`，使用独立签名及用户提供的头像。不会覆盖官方 SFA、NekoBox 或 Throne。

## 安装与手测

1. 普通 ARM64 手机安装 `GreyWolf-KEX-0.11.0-arm64-v8a.apk`；x86_64 安卓设备使用对应包。不确定架构可安装 `universal` 包。最低 Android 7.0（API 24）。
2. 将 `Example-KEX-Android.private.json` 传到手机。打开应用，在「配置」页点添加，选择「从文件导入」，选中该 JSON，再选择导入的配置。
3. 回到仪表盘启动，允许 Android 的 VPN 请求；无需 root。初次打开不会自动连接。手机上已有 VPN 应先停止。
4. 普通浏览器打开网页 Speedtest，手动选定与对照客户端相同的测速服务器，再测试网页、视频和常用应用。
5. 日志出现「KEX 已连接：HTTPS 握手完成，业务使用直连 UDP」才说明实际建立了连接。界面服务运行并不等于握手已经成功：首次流量才触发握手。
6. 临时网络故障和 QUIC 断线后自动重连；切网会废弃旧会话并在新接口重建。认证、证书或协议校验失败会停止重试，修正配置后手动停止再启动。已断开的 TCP 下载/UDP 会话不能原地恢复，应用需要发起新请求。

节点文件含设备私钥和握手接入令牌，只供本人测试。APK 本身不内置节点凭据；交付的 private ZIP 包含该节点文件，不能作为公开下载包。

## 传输与路由

- 首次连接通过 HTTPS KEX 建立会话，业务直接使用服务器 UDP/QUIC。没有 WSS，也没有在安卓上额外启动一个外部代理进程。
- 配置与当前 Windows 原生测试节点相同，但不继承 Windows 源 IPv4、网卡名或 CLI TUN 参数。
- TUN 使用 gVisor、MTU 1400，同时接管 IPv4/IPv6；公网走 KEX，局域网直连。
- DNS 劫持到内置解析器，DoH 通过 KEX 出站访问；握手入口和 UDP 服务端使用明确 IP，不依赖先有代理 DNS。
- HTTPS TCP 和服务器 UDP 套接字使用宿主 sing-box 直连拨号器，经 Android `VpnService.protect` 排除出本机 VPN；保护失败会中止拨号。
- 保留 TLS 证书验证。入口 IP 使用现有已验证配置；不做自动换入口或未验证的降级。
- 关闭上游客户端自动更新入口，后续用同签名的实验 APK 更新，避免丢失自定义出站支持。签名私钥保存在本机用户私密目录。

## 来源与复现

Android GUI 固定使用 `SagerNet/sing-box-for-android` 的 `fc21909df7a3f0fc9435f3866fb6a4960711aa5f`（1.14.2）作为兼容基线，修改在相邻仓库 `sing-box-for-android-kex` 的 `codex/android-kex` 分支。

本轮查询时上游 dev 已到 1.15.0-alpha.13；没有直接升级实验核心的依赖。现有 sing-box 分支基线是 1.14，选 1.14.2 是为了匹配移动端接口。

核心构建使用 Go 1.26.3、NDK 28.0.13004108；GUI 使用 JDK 21、Gradle 9.7.0、Android SDK 37.1。编译 SDK 版本不代表要求手机运行该版本 Android。

```powershell
# 在 dual-hy2 仓库执行；相邻依赖源码和 Android GUI 已检出。
python scripts/hdm/build-android-kex.py
python scripts/hdm/prepare-android-gui.py --source ../sing-box-for-android-kex --icon <头像文件路径>
python scripts/hdm/package-android-kex.py --config <本机私密KEX配置路径>
```

构建脚本把 `Throne-hdm/core/internal/kexoutbound` 逐文件复制到隔离的 sing-box 源码，并在 libbox 的上下文工厂注册出站。每个文件 SHA256 记录在 build-info 中；没有修改现用的桌面核心仓库或全局 Go 模块缓存。隔离 fork 的 libbox 带有 KEX 导入，因此应始终使用脚本列出的 `kex_poc` 标签构建。

## 验证边界

- arm64、x86_64 libbox AAR 交叉编译；本地 KEX 适配器测试通过。
- 实际 Android 配置经 libbox 的 TUN/DNS/出站注册表检查通过；回环监听测试确认仅检查配置不会连接握手入口。
- APK 发布构建、签名、ZIP 完整性、ABI 与对齐检查结果以交付目录中的记录为准。
- 本轮没有在手机安装应用、启动 VPN、访问真实节点或运行手机测速。系统 VPN 授权、后台保活、耗电、厂商系统兼容性及切网行为仍需实测。
- 没有为手机重做服务器部署；也没有改动正在使用的 Windows TUN。

## 0.11.0 自动重连（2026-10-31）

原 0.10.0 适配器只握手一次；任何会话断开后保持关闭，网络接口变化还会直接关闭整个出站。新版将出站寿命与单次会话分开，由单个后台协程串行管理握手、释放及重连。

- 首次实际流量才启动会话管理；检查配置不会访问握手入口。启动后断线会主动重连，不需要等到下一条业务请求。
- 临时失败按 1、2、4、8、16、30 秒基准退避，每次附加 0–20% 抖动，最长 36 秒。稳定连接至少 30 秒后重置退避。
- 并发业务请求共用新握手；单个请求取消不会终止共享会话。切网取消旧尝试并跳过剩余退避，旧网络结果不能发布。
- 错误令牌/设备认证、证书错误、无效配置或协议响应不反复重试；HTTP 503、限流、网络超时等可重试。维持证书验证，不降级或自动更换入口。
- 安卓报告休眠或默认网络不可用时暂停新握手，唤醒后继续；不会在休眠状态反复尝试。手动停止会取消握手、退避和活动连接，等待管理协程退出。
- 新日志记录会话结束分类和持续时间，不打印原始对端错误或凭据。已有 QUIC 5 秒保活、30 秒默认空闲超时保持不变。

这次修复能够恢复失效会话，但没有断线现场日志，不能证明此前长期运行断开的具体根因；安卓休眠、网络变化、UDP 丢包及服务端关闭需要结合新日志继续定位。进程被系统杀死后，进程内重连逻辑也无法继续执行。

本轮本地验证：原生适配器及 boxmain 全包 race 连续 3 轮通过，kexpoc 全包 race 通过；新增覆盖无业务请求时主动重连、20 个并发请求共享新握手、临时 503 恢复、认证失败不重试、切网取消在途握手、退避/休眠期间停止、休眠唤醒恢复和退避上限。安卓构建前再运行同一适配器测试。
